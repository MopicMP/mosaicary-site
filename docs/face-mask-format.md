# Формат разметки лица

Это **контракт**, а не описание реализации. Его читают две независимые
реализации — Java в моде (`FaceMask`) и TypeScript на сайте — и обе проверяются
одним набором эталонных строк: `test/Eyes/mask-fixtures.json`.

Так сделано потому, что два кодировщика одного формата **расходятся молча**. Не
падают, не ругаются — просто однажды разметка, сделанная в браузере, оказывается в
игре сдвинутой на пиксель, и найти день, когда это началось, уже нельзя. Эталонные
строки ловят это в тот же час.

## Что описывается

Квадрат лица скина: 8×8 в шестьдесятчетвёртых, то есть `u` 8..16, `v` 8..16 при
любом размере картинки. Для каждой клетки говорится, чем она является.

**Четыре вида меток:**

| | что это | зачем отдельно |
|---|---|---|
| `EYE` | радужка и зрачок | это то, что двигается при взгляде |
| `WHITE` | белок | это то, что показывается на месте уехавшей радужки |
| `BROW` | бровь | её поднимает выражение |
| `LASH` | ресница | **едет с веком, а не со лбом** — потому и не бровь |

**Два слоя:**

| | где на скине | |
|---|---|---|
| `FACE` | `u` 8..16 | само лицо |
| `OVER` | `u` 40..48 | верхний слой поверх него |

Слой — часть ответа, а не примечание к нему. HD-скины сплошь и рядом рисуют
подробную ресницу поверх простой или радужку на верхнем слое над белком на нижнем;
это разная геометрия на разной глубине, и радужку с верхнего слоя двигать надо на
верхнем слое.

Итого **восемь масок**: 4 вида × 2 слоя. Порядок фиксирован:

```
0 EYE/FACE   1 EYE/OVER   2 WHITE/FACE  3 WHITE/OVER
4 BROW/FACE  5 BROW/OVER  6 LASH/FACE   7 LASH/OVER
```

то есть индекс = `вид * 2 + слой`.

## Размер сетки

`size` — сколько клеток лицо в ширину. Восемь для обычного скина, до 256 для скина
шириной 2048. Всегда степень двойки от 8 до 256, потому что скин это 64 в ширину
умноженное на степень двойки.

Фиксированной сетки, которая описала бы все лица, не существует — это измерено на
пятидесяти HD-скинах: при 16 клетках глаз описывается точно на 15 лицах из 50, при
32 — на 18, при 64 — на 26. Поэтому сетка **своя у каждого скина**.

## Порядок битов

Бит `n` — это клетка `x = n % size`, `y = n / size`. То есть построчно сверху вниз,
слева направо, начиная с левого верхнего угла лица.

## Кодирование

```
size ":" runs "/" runs "/" runs "/" runs "/" runs "/" runs "/" runs "/" runs
```

- `size` — шестнадцатеричное число;
- восемь групп, разделённых `/`, в порядке из таблицы выше;
- группа — длины пробегов через `.`, шестнадцатеричные, **чередуя пусто и
  помечено, начиная с пустого**;
- пустая группа (`""`) означает, что ничего не помечено. Обычно так выглядят семь
  групп из восьми;
- неразмеченное лицо кодируется **пустой строкой**, а не строкой из восьми пустых
  групп.

Пример: лицо 16×16, помечены четыре клетки радужки на самом лице, больше ничего.

```
10:23.2.e.2.d1///////
```

Длины пробегов, а не шестнадцатеричные биты, потому что маска огромная и почти
пустая: лицо 256×256 — это 65 536 бит на маску, восемь раз, на каждый костюм. То,
что размечает человек, — несколько сплошных пятен, а сплошное пятно это два числа
при любом размере сетки.

## Правила чтения

Эти правила существуют, чтобы **чужая или испорченная строка стоила один костюм, а
не весь мир**.

1. Нечитаемая строка = неразмеченное лицо. Никаких исключений наружу.
2. `size` вне 8..256 или не степень двойки — округляется вниз до допустимой.
3. Пробеги, требующие больше бит, чем есть на лице, **обрезаются по краю**, а не
   выходят за массив.
4. **Три группы вместо восьми** — маска старого вида, до ресниц и слоёв. Читается
   как `EYE/FACE`, `WHITE/FACE`, `BROW/FACE`. Гардеробы, размеченные до этого,
   не теряются.
5. Любое другое число групп — неразмеченное лицо.

## Сведение к 8×8

Всё, что моргает и водит глазами, пока говорит на 8×8. Мелкая маска сводится так:

- клетка блока помечена — помечен весь блок (**любая**, а не большинство: веко,
  накрывшее лишний ряд, это мелкая некрасивость, а веко, промахнувшееся мимо
  глаза, — персонаж, который никогда не моргает);
- оба слоя складываются вместе;
- `LASH` складывается с `BROW` — у грубой карты нет для неё слова.

Сведение односторонне и это нормально: мелкая маска остаётся записью, грубая —
её видом.

## Эталонные строки

`test/Eyes/mask-fixtures.json`. Каждая запись — строка и то, что она означает,
разобранное по клеткам. Обе реализации обязаны сойтись на всех.

Добавляя случай, добавляй его **в файл**, а не в тест одной из сторон: случай,
известный одной реализации, — это ровно та дыра, ради которой файл заведён.
