# Сайт моделей Blockbench

Каталог моделей для Blockbench и только для него: загрузить свои `.bbmodel`,
посмотреть чужие в 3D прямо на странице, вместе с анимациями, скачать и открыть в
Blockbench. Публикует любой, кто вошёл через Discord или GitHub.

Имя сайта — Mosaicary, и с 10 октября 2026 года он стоит на
[mosaicary.com](https://mosaicary.com). Плагин, который приносит этот каталог
внутрь редактора, лежит отдельно: [MopicMP/mosaicary](https://github.com/MopicMP/mosaicary).

Первая версия — модели. Скины придут во второй, анимации в третьей. Оба раздела
уже стоят в шапке и отвечают страницей «скоро»: ничего не убрано, просто ещё не
открыто.

## Запуск

```sh
npm install
npm run db:local   # завести или обновить локальную базу
npm run dev        # страница на 5173, Worker на 8787, /api проксируется
```

```sh
npm run build      # проверка типов и файлы страницы в dist/web
npm test           # разбор моделей, правила, фильтры, вход
npm run check      # типы: страница и Worker
npm run dev:skins  # сайт скинов, как он был, со своим старым сервером на 3000
```

Windows: `run.bat` — то же самое меню, двойным щелчком. Пункт dev сам обновляет
локальную базу перед запуском, и меню возвращается после любой задачи, включая
упавшую.

**Ничего ставить и заводить не надо.** `wrangler dev --local` держит базу D1 и
хранилище R2 у себя, в `.wrangler/state`, и в git это не попадает. Секреты для
входа Worker берёт из `../.env` (весь файл целиком, только локально).

## Как это устроено

Две половины на одном адресе.

| | |
|---|---|
| Страница | статические файлы, которые отдаёт тот же Worker (`assets` в `wrangler.jsonc`); адреса вроде `/ru/models/<id>` файлами не существуют и отвечают `index.html` со статусом 200, поэтому ссылка на модель открывается сразу |
| `/api/*` | тот же Cloudflare Worker, база в D1, файлы и картинки в R2 |

GitHub Pages для страницы не используется: это был бы второй origin, куда не
поедет cookie входа, а формат `_redirects` там не читается вовсе.

**Файл модели разбирает браузер, а не сервер.** Страница сама читает `.bbmodel`,
вычищает из него пути к папкам на диске загрузившего (в них бывает имя
пользователя компьютера), считает, что внутри, рисует картинку для карточки и
только потом отправляет. Файл, который не модель, отклоняется на месте, с
причиной, и никуда не уходит. Worker хранит то, что ему прислали, и следит за
правилами: квоты, лицензии, копии чужих моделей, жалобы.

Чего Worker не может проверить сам — сходится ли файл с тем, что про него
сказали, — проверяет каждый, кто модель открыл. Расхождение отправляет модель в
очередь к тому, кто ведёт сайт.

| | |
|---|---|
| `src/` | страница: React + Vite, 3D на three.js |
| `worker/` | API: вход, модели, жалобы, очередь |
| `shared/` | то, что нужно обеим сторонам: разбор `.bbmodel`, правила, форма ответов |
| `migrations/` | схема базы D1 |
| `server/` | сайт скинов, ждёт второй версии; в сборку моделей не попадает |
| `test/` | vitest |

**Ключи API — для плагина Blockbench.** Их создают на «Моих моделях», а плагин
шлёт ключ в `Authorization: Bearer`. Запрос с `Authorization` судится только по
ключу, cookie не смотрится. Ключу открыт только белый список маршрутов в
`worker/keyRules.ts`. Частоту запросов с ключом ограничивают привязки `KEY_READS`
и `KEY_WRITES` (`wrangler.jsonc`, 300 и 30 в минуту на аккаунт). Отсюда три
следствия при работе с сайтом:
- локальный ограничитель miniflare бывает сломан после падения среды выполнения:
  на каждый вызов он отвечает «internal error». Сайт тогда пропускает запрос и
  пишет в журнал «rate limiter failed, request let through», так что локально
  предел может не срабатывать;
- плагин с ключом проверяют прямо против Worker (`http://127.0.0.1:8787`), а не
  через Vite: Vite сам отвечает на предварительный запрос CORS и чужому адресу его
  не разрешает;
- если закрыть копию сайта паролем HTTP Basic, браузер будет слать `Authorization:
  Basic` с каждым запросом. Тогда вход по cookie и все изменения на этой копии
  молча перестанут работать: такой запрос считается запросом с ключом.

Живые проверки маршрутов: `test/live/talk.mjs` (обсуждения) и `test/live/keys.mjs`
(ключи), команды в их шапках.

## Своя копия

Всё ниже — действия на своём аккаунте Cloudflare и в порталах входа. Для местной
работы ничего из этого не нужно: `npm run dev` поднимает и базу, и хранилище у себя.

1. Свой домен в Cloudflare.
2. База и бакет:
   ```sh
   npx wrangler d1 create models-site       # id базы вписать в wrangler.jsonc
   npx wrangler r2 bucket create models-site-files
   npx wrangler d1 migrations apply models-site --remote
   ```
3. Секреты Worker, каждый через `npx wrangler secret put <имя>`:
   `SESSION_SECRET`, `DISCORD_APP_CLIENT_ID`, `DISCORD_APP_CLIENT_SECRET`,
   `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `ADMINS`
   (`discord:<id>,github:<id>`), `OPERATOR_EMAIL`. Адрес сайта задаётся не
   секретом, а переменной `PUBLIC_ORIGIN` в `wrangler.jsonc`.
4. Адрес возврата во входе:
   - Discord: `<адрес сайта>/api/auth/discord/callback`;
   - GitHub OAuth App: `<адрес сайта>/api/auth/github/callback`. У GitHub одно
     приложение на один адрес возврата, поэтому для локальной работы нужно второе,
     с `http://localhost:5173/api/auth/github/callback`.
5. `routes` в `wrangler.jsonc` на свой домен и `npx wrangler deploy`.

Обязательный `https` придётся включить руками (`Always Use HTTPS` в зоне): cookie
входа помечена `Secure`, и по `http` вход тихо не работает.

Квота на человека и дневной предел загрузок в `shared/modelRules.ts` — прикидки,
а не замер. Их стоит пересмотреть, когда появятся настоящие загрузки.

## Рабочие заметки

Ссылки вида `docs/что-нибудь.md` в комментариях ведут на заметки, которые лежат в
основном дереве проекта и в этот репозиторий не входят. Исключение одно —
`docs/face-mask-format.md`: это контракт, у которого две независимые реализации
(TypeScript здесь и Java в моде), и он нужен обеим.

У этого же контракта есть единственный шов, оставшийся от разделения:
`test/faceMask.test.ts` читает эталонные строки по пути `../../test/Eyes/mask-fixtures.json`,
то есть из основного дерева. В отдельной копии этой проверки не будет чем питаться,
и `npm test` на ней падает; остальные сорок с лишним проверок проходят. Эталоны
нарочно не скопированы сюда: один формат с двумя наборами эталонов — это ровно то
тихое расхождение, от которого контракт и заведён.
